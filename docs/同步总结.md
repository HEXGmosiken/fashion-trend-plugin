## 二、数据层（A 的改动）

### 术语表：271 → 300 条

每条新增四个字段：

| 字段 | 作用 |
|---|---|
| `criterion` | 判定标准：什么情况算命中这个词 |
| `source` | 出处：术语从哪来，便于溯源 |
| `confusable` | 易混词：和哪些词不要混为一谈 |
| `parent` | 上位词：归属到更大的类 |

## 三、分析层（B 的改动）

### 新增样本资格模块 `src/core/eligibility.ts`

在统计之前先剔除不合格样本，剔除原因分七类：窗口不符、主题季不符、日期异常、品牌稿、来源类型不符、未知来源、广告。

这一步很关键：以前只要证据编码了就算进分母，现在先过资格再算比例。

### 审计规则：16 条 → 23 条

新增规则包括：

- 未来日期、抓取日早于发布日
- 摘录过短（少于 20 字）
- 主题季与窗口不匹配
- 未登记来源
- 同链接重复、跨集团转载

完整清单在 `docs/审计规则.md`，每条有触发条件和处理建议。

### 去重阈值用真实语料校准

`docs/去重阈值校准.md` 记录了校准过程和复算结果，阈值不再拍脑袋定。

### 命题模板

新增 `data/claims.template.json`，新命题照模板填就行，不用猜字段。

## 七、怎么看到新结果

报告是生成物，不进仓库，拉完代码必须重新生成：

```bash
git -c http.version=HTTP/1.1 pull
pnpm ingest          # 自动模式
pnpm real            # 精细模式
pnpm test            # 64 个用例
```

然后打开 `reports/index.html`。
