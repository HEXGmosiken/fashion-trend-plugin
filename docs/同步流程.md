# 同步流程（手动操作版）

下次自己拉代码、跑报告、推上去，照这个顺序做。

## 一、日常同步：三步

### 第 1 步：看清现状

```bash
cd D:\chajian
git status
```

看三件事：

- 当前在哪个分支（应该是 `main`）
- 有没有未提交的改动
- 有没有 `ahead` / `behind`

### 第 2 步：拉取并变基

```bash
git fetch origin
git log --oneline HEAD..origin/main      # 别人新提交了什么
git rebase origin/main
```

`rebase` 会把你的本地提交挪到最新代码之上，历史保持一条直线，比 `merge` 干净。

如果工作区有未提交的改动，先 `git stash`，变基完再 `git stash pop`。

### 第 3 步：跑测试、重新生成报告

```bash
pnpm test
pnpm ingest      # 自动模式
pnpm real        # 精细模式
```

报告是生成物，不进仓库，所以每次拉完代码都必须重新生成，否则看到的是旧报告。

## 二、推送：一条命令 + 两个备用手段

```bash
git push origin main
```

### 如果报 `Failed to connect to github.com port 443`

这是网络被重置，不是权限问题。按顺序试：

```bash
# 1. 强制 HTTP/1.1
git -c http.version=HTTP/1.1 push origin main

# 2. 多试几次（经常第二次就通）
# 3. 换网络：手机热点最有效，4G 一般不挡 443
```

### 如果报 `non-fast-forward`

说明远程有你没有的提交，先同步再推：

```bash
git pull --rebase origin main
git push origin main
```

### 如果报 `Changes must be made through a pull request`

说明分支保护生效了。管理员可以绕过，但建议改走分支流程（见第四节）。

## 三、怎么确认真的成功了

**不看最后一行，看远程 SHA。**

```bash
git status
# 显示 "Your branch is up to date with 'origin/main'" 才算成功
```

或者：

```bash
git log --oneline -1
git ls-remote origin main
```

两个 SHA 一样才算推上去了。

`Everything up-to-date` 这句话不可信——推送中途断开时也会打印，不代表成功。

## 四、自己的改动走 PR（推荐）

### 1. 开分支

```bash
git switch -c feat/你的模块-具体事
```

命名：`feat/report-layout`、`fix/image-alt`、`docs/sync-guide`。

### 2. 改完提交

```bash
git add -A
git commit -m "feat(render): 目录改成两排"
```

### 3. 推分支

```bash
git push -u origin feat/你的模块-具体事
```

### 4. 开 PR

浏览器打开仓库，会看到黄色的 **Compare & pull request**，点进去：

- 标题写清楚做了什么
- 描述里写「改了什么 / 怎么验证的」
- 指定 reviewer

### 5. 合并

Reviewer 通过后，点 **Squash and merge**，然后 **Delete branch**。

### 6. 回到 main 同步

```bash
git switch main
git pull --rebase origin main
git branch -d feat/你的模块-具体事
```

## 五、自己的 PR 能不能自己审核

**不能。** 这是 GitHub 的硬限制：自己的 PR 上，`Approve` 按钮是灰的，提示 "You can't approve your own pull request"。

三条可选做法：

| 做法 | 结果 | 建议 |
|---|---|---|
| 找 B 或 C review 一下 | 正常通过，有第二个人看过 | 推荐 |
| 管理员身份绕过保护直接合并 | 能合，等于自审自过 | 紧急时用 |
| 把 required approvals 临时改成 0 | 谁都能自合 | 不推荐，影响所有人 |

管理员的合并按钮仍然可用，因为分支保护里「管理员豁免」是开着的。绕过时 GitHub 会记一条 bypass 记录，答辩时如果被问，这是可以解释的。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `ahead 2` 一直不消失 | 没推送成功 | 按第二节重试 |
| `rebase` 报冲突 | 两人改了同一行 | 打开冲突文件，保留需要的版本，`git add` 后 `git rebase --continue` |
| 拉下来报告没变 | 报告是生成物 | 跑 `pnpm ingest` / `pnpm real` |
| 图片全部裂开 | 资源目录没同步 | 检查 `assets/img` 是否在本地 |
| 术语表变多了但趋势没变 | 抽取有最小样本门槛 | 正常，说明新词在语料里出现次数不够 |

## 七、每次开工前的三十秒

```bash
git status              # 在 main 吗，干净吗
git fetch origin        # 有更新吗
git rebase origin/main  # 跟上
pnpm test               # 还是绿的吗
```

养成这个习惯，就不会出现「改了三天发现跟别人冲突」的情况。
