# trend-lab　服装趋势分析插件

把一批文章，变成一份能翻、能查、能复核的趋势报告。

两种用法：

- **自动模式**：把文章丢进去，自动抽取趋势，直接出图文报告。适合快速看一季的风向。
- **精细模式**：人工编码证据，按命题做前后对比，每条结论都挂原文。适合交付给学长验收。

两种模式共用同一套渲染和证据台账。

---

## 一分钟上手

需要 Node.js 22.18 或更高版本，首次先装依赖。

```bash
pnpm install
pnpm ingest
```

打开 `reports/index.html`，从那里进任何一种报告。

`pnpm ingest` 默认读 `data/articles.real.json`（仓库里那 50 篇文章），输出到 `reports/auto/`。

换成你自己的文章：

```bash
pnpm ingest --articles my/articles.json --out my-report
```

**输出统一放在 `reports/` 下**，一共三个子目录：

| 目录 | 内容 |
|---|---|
| `reports/auto/` | 自动模式：`deck.html`、`trends.md`、`trends.json` |
| `reports/curated/` | 精细模式：`deck.html`、`trends.md`、`report.md`、`report.json`、两个 CSV |
| `reports/demo/` | 示例数据，只验证链路 |

`trends.md` 是文字版趋势报告，可以直接贴进 Word 或飞书。

> 想了解实现细节，看 [`docs/插件详解.md`](docs/插件详解.md)。那份是给汇报用的。

## 投喂什么格式

一个 JSON 文件，里面是文章数组。最少四个字段：

```json
{
  "articles": [
    {
      "id": "A001",
      "title": "2027 春夏巴黎时装周趋势盘点",
      "url": "https://example.com/article",
      "date": "2026-10-05",
      "source": "Vogue Runway",
      "text": "正文全文……",
      "image": "../assets/img/cover.jpg"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一编号，报告里用来回链 |
| `title` | 是 | 标题 |
| `url` | 是 | 原文链接，报告里每句引用都可点回 |
| `date` | 建议 | 发布日期，没有就留空，报告会标「日期未标注」 |
| `source` | 是 | 媒体名，用于去重和统计来源数 |
| `text` | 是 | 正文纯文本 |
| `image` | 否 | 配图路径，有图报告就是图文版，没图退回文字版 |

文章可以中外混排，插件会自动识别中英文关键词。

## 报告长什么样

一屏一条趋势，从上到下：

1. **图墙**：文章配图，满宽
2. **趋势名 + 英文代号**：例如「轻薄透视 / Sheer Layers」
3. **一句话立意**：这条趋势在解决什么穿衣问题
4. **三条要点**：自动模式是数据要点（出现篇数、来源数、首发日期），精细模式是构型（肩线、腰线、量感）
5. **形状词云**：词的粗细和大小由出现篇数决定，整体排成一个心形
6. **数据箭头**：有统计口径时显示 `↗ 23 点` 和两季对比条
7. **原文出处**：三条引用，带媒体名、日期、链接

翻页有阻尼缓动，右下角可以关掉。左侧细导航跟着滚动走。

## 六个板块

| 板块 | 回答什么问题 |
|---|---|
| 廓形款式 | 这一季衣服长什么形状 |
| 结构工艺 | 这个形状是怎么做出来的 |
| 材质肌理 | 用什么料子做出这个手感 |
| 色彩 | 这一季在用什么颜色 |
| 风格美学 | 整体在表达哪一种气质 |
| 场景穿着 | 这些衣服穿去哪儿 |

自动模式每个板块取最活跃的三条，最多十八条；精细模式是人工定的十二条。

---

## 自动模式做了什么

1. 用一份 **204 条术语表**扫描全文，每条有中文名、英文名、别名、一句话定义
2. 统计每个词出现在多少篇、和谁同篇出现
3. 按板块挑出最活跃的词，每词一条趋势；「廓形」「版型」这类分析用语不当标题
4. 给每条趋势抽三句原文引用，优先不同来源
5. 挂上对应文章的配图
6. 在开头生成一段「总述」：论点由人写，数据由程序填
7. 渲染成报告

**它只做统计和摘句，不写判断。** 所以自动模式里不会出现「明年会火」这类话，只会有「24 篇提到，占样本 48%」。

## 语料库

`data/corpus/` 是本项目自己攒的语料，三份文件：

| 文件 | 内容 | 规模 |
|---|---|---|
| `terms.json` | 专业术语：中文名、英文名、别名、一句话定义、所属板块 | 204 条，覆盖六板块 |
| `patterns.json` | 分析句式：24 个模板，每个带槽位、两个例句、使用场景 | 8 类（转变/结构/搭配/色彩/论据/对比/收束/论点） |
| `summary.json` | 总述：一句总论点、三段论据、一条反证、一句收束 | 人工撰写，挂趋势名 |

**术语表解决什么**：以前「薄纱 / 网纱 / 欧根纱」各算一条，统计会翻倍；现在合并到同一条，别名一起命中。

**句式库解决什么**：报告不再只会写「X 篇提到 Y」，可以用「从 A 转向 B」「A 成为 B 的替代品」这类专业写法。外部 26 篇文章的验证结果见 [docs/句式验证.md](docs/句式验证.md)。

**总述解决什么**：给报告一个「总分总」的骨架。论点是人写的判断，数据行由程序从趋势里取，两边不混。

## 精细模式

自动模式证明「有这个东西」，精细模式证明「它真的在变」。

流程：人工收集文章 → 人工编码 → 冻结命题 → 跑对比 → 出报告。

```bash
pnpm real     # 用 50 篇真实语料 + 十二条人工趋势，输出到 reports/curated/
pnpm analyze  # 换自己的数据：--input/--claims/--sources/--trends
```

精细模式的核心是**双时间窗对比**：同一个信号在上一季和这一季的报道里各出现多少次，用 Wilson 区间判断差异是不是真的。

当前跑出来的三条：

| 命题 | 2026 秋冬 | 2027 春夏 | 变化 | 置信度 |
|---|---|---|---|---|
| 轻薄透视 | 27% | 50% | 高出 23 点 | 中 |
| 格纹 | 27% | 13% | 低 14 点 | 中 |
| 定制西装 | 55% | 56% | 基本持平 | 低 |

第三条最值得说：媒体里「西装回归」的声音很大，但数据不支持，报告就写「基本持平」。

---

## 证据怎么留

每条结论都能回到底层：

- 趋势页的引用带链接，点开是原文
- `reports/curated/report.md` 是命题版文本报告，附录里有完整证据台账
- `reports/curated/evidence.csv` 是表格版，可以用 Excel 逐行核对
- `reports/curated/report.json` 是给程序读的结构化结果

自动模式同样保留引用：每条趋势至少两句原文，来源和日期都在。

## 图片与版权

`_tools/images.py` 会从文章页抓头图，只保留够大的（宽 700、高 420 以上），统一压到 1400 宽。

当前 50 篇里拿到 41 张。图片来自媒体报道，**仅限内部演示**，不要公开分发。

## 命令

| 命令 | 作用 |
|---|---|
| `pnpm ingest` | 投喂文章，自动出报告 |
| `pnpm real` | 真实语料 + 人工趋势，出精细报告 |
| `pnpm demo` | 合成示例数据，验证链路 |
| `pnpm analyze` | 自定义数据的完整分析 |
| `pnpm validate` | 检查输入 JSON 格式 |
| `pnpm check` | 只跑质量检查 |
| `pnpm test` | 单元测试 |
| `pnpm typecheck` | 类型检查 |

所有命令都支持 `--out` 指定输出目录。`ingest` 额外支持 `--articles`。

## 已知限制

1. **配图不一定贴题**：抓的是文章头图，有时是整季合辑，和具体趋势对不上。
2. **中文站配图少**：多数中文媒体的图是懒加载，抓不到。
3. **自动模式没有趋势判断**：它只告诉你「哪些词被反复提到」，不告诉你「为什么」；判断在总述里，是人写的。
4. **术语表是有限的**：204 条之外的说法抽不到，新词需要补进 `data/corpus/terms.json`。
5. **句式库以中文模板为主**：英文固有句式（is the new / is back / has replaced）只收了 6 条，写英文报告还不够用。
6. **图片版权**：只做内部演示。

## 交给主项目调用

```ts
import { renderMagazine } from "./src/core/render/magazine.ts";
import { extractTrends } from "./src/core/auto.ts";
import fs from "node:fs";

const { book, report } = extractTrends(
  JSON.parse(fs.readFileSync("data/articles.real.json", "utf8")).articles,
);

const html = renderMagazine(book, report);
```

`book` 是纯数据，可以直接给前端或 API 用。
